MTGEDH Oracle IR Architecture & Execution Loop

Version: 2026-06-12 (batch 279)  |  Repository: MTGEDH  |  Audience: Contributors working on card behavior and server integration

1. Purpose

Oracle IR (Intermediate Representation) is the canonical pipeline for turning oracle text into game state changes. The end goal is a single path:

oracle text → parse → OracleEffectStep[] → execute → server sync → resolution UI → resume

Layers 1–2 (parse + dry-run execute) are complete for Commander scope. Layer 3 (live server integration) is partial: production runs IR-primary, but legacy fallbacks still run when IR returns incomplete.

2. Three Layers

LayerLocationResponsibilityStatus
1 — Parserules-engine/src/oracleIRParser.tsparseOracleTextToIR() → stepsGreen (~30k cards)
2 — Executerules-engine/src/oracleIRExecutor.tsapplyOracleIRStepsToGameState()Green (triggers 100% assisted)
3 — Integrateserver/src/state/modules/oracleIr*.tsLive state, queue, resumePartial
Rule: Never call applyOracleIRStepsToGameState on live server state. Always use applyOracleIRStepsOnServer.

3. Core Data Types

OracleEffectStep

Typed instructions in rules-engine/src/oracleIR.ts: draw, mill, create_token, add_counter, tap_or_untap, conditional, choose_mode, unknown (gap — must not return handled: true).

OracleIRExecutionContext

Built via buildOracleIRExecutionContext(): controller, source, targets, chosenObjectIds, xValue.

OracleIRExecutionResult

appliedSteps, skippedSteps (with reason codes), pendingOptionalSteps, pendingContinuationSteps, mutated state.

6. Execution Loop (Phases)

Phase A — Stack entry

  1. Activated → tryApplyOracleIRToActivatedAbility (oracleIrAbilityExecution.ts)
  2. Triggered → tryResolveTriggerViaOracleIR (oracleIrTriggerExecution.ts)
  3. Spell → tryResolveSpellViaOracleIR (oracleIrSpellExecution.ts)

Each: extract effect text → parseOracleTextToIR → collect steps → check oracleIrStepWiring.ts runtime wiring.

Phase B — All-or-nothing gate

Invariant: Multi-step effects must complete mandatory steps or return handled: false. Partial IR + legacy fallback = double tokens/effects (primary bug class).

Phase C — Server apply

applyOracleIRStepsOnServer in oracleIrServerZoneSync.ts:

  1. hydrateOracleIRPlayerZonesFromContext
  2. applyOracleIRStepsToGameState with haltOnPlayerChoiceRequired: true
  3. Sync zones, counters, tokens, delayed flicker returns
  4. queue*ChoicePromptsFromOracleIRResult per paused step kind

Phase D — Resolution queue bridge

Client: resolutionStepPrompt → modal in App.tsx → submitResolutionResponse → maybeResumeOracleIRStepsAfterResolution.

Phase E — Effect Program

For multi-choice chains: rules-engine/src/effectProgram.ts, startOracleEffectProgramOnServer, resumeEffectProgramResolution. Production for optional trigger yes/no and fateseal/clash; not yet default for modal choose_mode spells.

7. Ability-Type Loops

Triggered abilities

Game event → detect*Triggers() → stack (APNAP)
  → tryResolveTriggerViaOracleIR()
       ├─ Effect Program? → startOracleEffectProgramOnServer
       ├─ applyOracleIRStepsOnServer()
       └─ handled? done : executeTriggerEffect() legacy
  → resolution prompts → resume → broadcast

Tap batching: collectTapTriggersForTapEvent() — "one or more X become tapped" fires once per event.

Activated abilities

interaction.ts → costs paid → stack
  → tryApplyOracleIRToActivatedAbility()
       → collectActivatedAbilitySteps() (text after "{cost}:")
       → applyOracleIRStepsOnServer()
  → queue + resume

Most complete IR integration path.

Spells

stack → tryResolveSpellViaOracleIR() [SPELL_PRIMARY]
  → handled? done
  → else categorizeSpell() → executeSpellEffect()
  → else oracleIrUncategorizedSpellFallback

9. Adding New Behavior

  1. Parser — oracleIRParser*.ts + rules-engine test
  2. Executor — oracleIRExecutor*StepHandlers.ts
  3. Wiring — trigger-runtime-wiring.ts step kind sets
  4. Server queue — queue*FromOracleIRResult + resolution.ts resume
  5. Integration test — server/tests/oracle-ir-*.ts with PRIMARY=1
  6. Retire — legacy regex if superseded
Forbidden: card-name routing, new KNOWN_* table rows, bespoke executeTriggerEffect branches. See .cursor/rules/oracle-ir-no-bespoke-handlers.mdc.
